# Optimistic workspace updates

Routine enquiry commands now use TanStack Query mutations with optimistic cache updates: notes, call logs, scheduling/rescheduling/cancelling follow-ups, ordinary stage changes and customer/qualification details and unverified payment entry. Contact previews propagate across enquiries belonging to the same customer. Trip-fit ranking remains authoritative on the server. Non-financial trip edits preview immediately; price/deposit changes wait for confirmation. Marking an in-app reminder seen also updates immediately.

Payment verification/reversal, quotations, confirmed bookings, ranking overrides, deletion, creation, publication and permission/security changes remain server-confirmed. No server-generated customer/enquiry identity, payment approval or booking reference is fabricated.

The shared mutation hook cancels in-flight CRM reads using AbortSignal before patching cache. It prevents overlapping writes and disables conflicting controls, scopes cache changes to the signed-in identity, restores affected records on errors, and reconciles CRM/reminders/customer-search caches with the server. Saving status is shown immediately; Saved appears only after success. Network/server/rate-limit errors offer a retry using the original payload and retained idempotency key. A retry still reaches the server when a lost response already committed and advanced the revision, preventing duplicate notes/actions. Business/revision conflicts are not silently rebased or automatically retried.

Reminder dismissal cancels pending reminder reads, hides the item immediately, restores it on error, and refetches afterward. CRM reconciliation defers reminder invalidation when dismissal is still pending.

Verification: five projection/rollback unit tests plus the existing focused suite (62 tests total); ten browser controls/workflow tests including delayed responses, rollback, lost-response reconciliation/idempotent retry, immediate trip edits, server-confirmed quotation changes, safe original-payment retries after interrupted responses, reminder rollback, mobile notes and customer search/deletion controls. TypeScript and Vite build pass. The existing bundle-size warning remains. Full local workerd tests remain blocked by Windows application control. Browser tests use synthetic API data; no live customer edits were used for validation. No schema migration, Meta activation or messaging change is required.

Payment entry previews remain unverified and do not increase verified funds or enable booking confirmation. Verification, additional payment entry and receipt attachment wait until the preview reconciles with the saved payment ID. Failure rolls back the preview; retry retains the original idempotency key. Removed the leftover Fictional terms only badge and Fictional amounts only booking footer. Delayed-response browser checks cover immediate unverified entry, rollback, safe retry, disabled verification until saved, and absence of those labels on both screens.
